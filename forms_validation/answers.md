# Ответы на вопросы для самоконтроля — Практическая работа №7

## 1. Какие HTML5-атрибуты используются для клиентской валидации и какую функциональность они предоставляют?

- required — поле обязательно.
- type — email, url, tel, number, date и др. — браузер проверяет формат.
- minlength / maxlength — ограничение длины текста.
- min / max / step — для чисел и дат.
- pattern — регулярное выражение для проверки значения.
- multiple — разрешает несколько значений (например, email через запятую).
- autocomplete — подсказки, не валидация, но улучшает UX.
- novalidate на форме — отключает встроенную валидацию.

Эти атрибуты дают базовую проверку без JavaScript и работают даже при отключённых скриптах.


## 2. В чём разница между novalidate атрибутом формы и отключением валидации через JavaScript?

novalidate — это HTML-атрибут на теге <form>. Он отключает встроенную браузерную валидацию целиком. При этом атрибуты required, pattern и т. д. остаются в разметке, но браузер их не проверяет. Удобно, когда вся валидация реализована на JavaScript.

Отключение через JS (например, form.noValidate = true) делает то же самое, но уже в рантайме. Можно включить/выключить динамически.

Разница в том, где задано отключение: в HTML — статично, в JS — динамично. По результату одинаково: браузер не проверяет поля сам.


## 3. Как правильно связать <label> с полем ввода и почему это важно для доступности?

Два способа:
1) Через for у label и id у input:
<label for="email">Email</label>
<input id="email" type="email">

2) Обернуть input внутрь label:
<label>Email <input type="email"></label>

Важность:
- Скринридеры читают подпись при фокусе на поле.
- Клик по подписи ставит фокус в поле — удобнее на мобильных.
- Это требование WCAG для доступности форм.


## 4. Какие типы полей input наиболее подходят для разных видов данных?

- email — для email, браузер проверяет формат, показывает @ на мобильной клавиатуре.
- tel — для телефона, на мобильных открывается цифровая клавиатура.
- password — скрывает ввод.
- number — для чисел, показывает числовую клавиатуру, поддерживает min/max/step.
- date / time / datetime-local — выбор даты и времени.
- url — проверяет формат ссылки.
- search — поле поиска.
- color — выбор цвета.
- range — ползунок.

Правильный type улучшает UX и валидацию.


## 5. Как работает валидация с помощью pattern атрибута и в каких случаях его следует использовать?

pattern принимает регулярное выражение. Значение считается валидным, если целиком соответствует шаблону.

Пример:
<input pattern="^\+?[0-9\s\-()]{10,18}$">

Используется, когда нужен специфичный формат: телефон, индекс, номер карты, логин. Не стоит злоупотреблять: слишком строгий pattern мешает пользователю. Например, для email лучше type="email", а не свой pattern.


## 6. Какие события JavaScript используются для реализации валидации в реальном времени и почему?

- input — срабатывает при каждом изменении значения, пока пользователь печатает. Удобно, чтобы сразу показывать ошибку.
- blur — когда поле теряет фокус. Хорошо для первой проверки, чтобы не ругать пользователя во время набора.
- change — когда значение изменилось и поле потеряло фокус; удобно для checkbox, select, radio.
- submit — при отправке формы: финальная проверка всех полей.

Обычно комбинируют: не проверять на input, пока пользователь ещё ничего не ввёл, а после первой ошибки — уже проверять в реальном времени. Так меньше раздражения.


## 7. Как обеспечить доступность сообщений об ошибках для пользователей скринридеров?

- Связать сообщение с полем через aria-describedby:
  <input id="email" aria-describedby="email-error">
  <p id="email-error" role="alert"></p>
- Пометить поле как невалидное через aria-invalid="true".
- Для динамических сообщений использовать role="alert" или aria-live="polite" — скринридер озвучит изменение.
- Не полагаться только на цвет: добавлять текст и иконку.
- Сообщения короткие и понятные, без технического жаргона.


## 8. В чём преимущества использования fieldset и legend для группировки полей формы?

fieldset группирует связанные поля, legend даёт группе название.

Преимущества:
- Семантика: понятно, что поля относятся к одной группе.
- Доступность: скринридеры читают legend перед каждым полем группы.
- Стилизация: можно оформить группу рамкой или отступами.
- Логика: удобно группировать radio/checkbox.

Пример:
<fieldset>
  <legend>Личные данные</legend>
  ...
</fieldset>


## 9. Как реализовать кастомную валидацию для сложных случаев (например, подтверждение пароля)?

Нужно проверять связь между полями. В обработчике:
- берём значение поля password;
- сравниваем со значением confirm;
- если не совпадают — показываем ошибку под confirm;
- при изменении password перепроверяем confirm.

Пример из работы:
if (value !== fields.password.input.value) return 'Пароли не совпадают.';

Такая логика не выражается стандартными атрибутами HTML5, поэтому реализуется на JavaScript.


## 10. Какие методы CSS используются для визуального отображения состояний валидности/невалидности полей?

- Псевдоклассы :valid и :invalid — работают с встроенной валидацией.
- :focus, :hover — состояния взаимодействия.
- :placeholder-shown — отличает пустое поле от заполненного.
- Кастомные классы .valid и .invalid, которые ставит JavaScript.
- :user-invalid / :user-valid — учитывают только поля, которых пользователь касался.

Цвет — не единственный индикатор: рядом с полем выводится текст ошибки и, при желании, иконка. Это требование доступности.
