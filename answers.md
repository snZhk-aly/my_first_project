# Ответы на вопросы
 
Три области Git:

Рабочая папка — где вы редактируете файлы.

Индекс (staging) — промежуточная зона, куда добавляются изменения перед коммитом.

Репозиторий — сохранённая история коммитов.
Отличаются уровнем: изменения идут из рабочей папки → в индекс → в репозиторий.

Команды:

git add — добавляет изменения в индекс.

git commit — сохраняет содержимое индекса как новый коммит в репозитории.

git push — отправляет коммиты на удалённый репозиторий.

Зачем информативные сообщения: чтобы понимать, что и зачем менялось, легче искать баги, откатывать изменения и работать в команде. «update» ничего не объясняет.

git add имя_файла vs git add .:

имя_файла — добавить только конкретный файл (точечно).

. — добавить все изменения в текущей папке.
Лучше первый, когда нужно закоммитить только часть правок; второй — когда всё готово к коммиту.

git status показывает: текущую ветку, изменённые/новые файлы, что в индексе, что нет. Вывод меняется: до add — файлы в «unstaged», после add — в «staged», после commit — рабочая папка чистая.

git remote add origin URL — привязывает удалённый репозиторий по адресу URL под именем origin. origin — просто стандартное имя для основного удалённого репозитория.

Флаг -u связывает локальную ветку с удалённой. После этого можно писать просто git push и git pull без указания ветки.

Ветка по умолчанию — основная ветка проекта. Сейчас обычно main, раньше — master. Важно, потому что от неё зависят команды, CI, настройки GitHub и соглашения в команде.

История коммитов: git log (или git log --oneline). Видно: хеш, автора, дату, сообщение коммита.

Если не сделать git add перед commit: изменения не попадут в коммит — закоммитится только то, что уже было в индексе (или коммит будет пустым/старым).
