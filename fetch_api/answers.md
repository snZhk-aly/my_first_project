# Ответы на вопросы для самоконтроля — Практическая работа №14

## 1. В чём разница между Fetch API и XMLHttpRequest? Какие преимущества предоставляет Fetch API?

XMLHttpRequest (XHR) — старый API на основе колбэков. Код получается громоздким, а промисы не поддерживаются из коробки.
Fetch API — современный стандарт на промисах. Работает с async/await, проще читается, встроенная поддержка заголовков (Headers), тела запроса (body), отмены через AbortController.

Преимущества Fetch:
- Промисы и async/await.
- Чистый и понятный код.
- Встроенные объекты Headers, Request, Response.
- Поддержка отмены (AbortController).
- Работает со стримами.

## 2. Как обрабатываются ошибки в Fetch API и почему ответ с HTTP статусом 404 не вызывает reject промиса?

Промис от fetch() отклоняется (reject) только при сетевых ошибках (нет интернета, неверный домен, CORS).
Если сервер ответил, пусть даже с ошибкой 404 или 500 — промис успешно резолвится объектом Response.

Поэтому нужно вручную проверять response.ok:
  const res = await fetch(url);
  if (!res.ok) throw new Error(`HTTP ${res.status}`);

## 3. Какие методы HTTP поддерживает Fetch API и в каких случаях используется каждый из них?

- GET — получить данные (по умолчанию).
- POST — создать новый ресурс.
- PUT — полностью заменить ресурс.
- PATCH — частично обновить ресурс.
- DELETE — удалить ресурс.
- HEAD — получить только заголовки.
- OPTIONS — предварительный запрос для CORS.

Метод указывается в options.method.

## 4. Как работать с заголовками запроса и ответа в Fetch API?

Запрос: передаются в объекте options.headers (как объект или new Headers()).
  fetch(url, { headers: { 'Content-Type': 'application/json', 'Authorization': 'Bearer token' } })

Ответ: читаются через response.headers.get('Content-Type').
Полезные заголовки:
- Content-Type — формат данных (JSON, HTML и т. д.).
- Authorization — токен авторизации.
- Accept — какой формат хочет клиент.
- Cache-Control — управление кэшем.
- Content-Length — размер тела.

## 5. В чём разница между PUT и PATCH запросами?

- PUT — полная замена ресурса. Если отправить только title, остальные поля (body, userId) перезапишутся как undefined.
- PATCH — частичное обновление. Меняются только переданные поля, остальные остаются как были.

PUT используется, когда нужно заменить объект целиком. PATCH — когда нужно обновить пару полей.

## 6. Как реализовать авторизацию в Fetch API?

- Basic Auth: Authorization: Basic base64(login:password).
- Bearer Token: Authorization: Bearer <токен>.
- API Key: X-API-Key: <ключ> в заголовках или в параметрах URL.

Токены лучше хранить в localStorage/sessionStorage (с осторожностью к XSS) или в HttpOnly cookie.

## 7. Какие способы отмены запросов существуют в Fetch API и когда их следует использовать?

Основной способ — AbortController.
Создаем контроллер: const controller = new AbortController();
Передаем сигнал: fetch(url, { signal: controller.signal });
Отменяем: controller.abort();

Используется:
- Таймауты (если сервер долго не отвечает).
- Отмена устаревших запросов (например, при быстром вводе в поиск).
- Уход пользователя со страницы.

## 8. Как работать с разными форматами данных в Fetch API?

Чтение ответов:
- JSON: response.json().
- Текст: response.text().
- Blob (бинарные файлы, картинки): response.blob().
- ArrayBuffer (сырые байты): response.arrayBuffer().
- FormData (формы, файлы): response.formData().

Отправка: в body можно передать строку JSON, FormData, Blob, ArrayBuffer.

## 9. Как оптимизировать производительность при работе с множественными запросами?

- Параллельные запросы через Promise.all, если данные независимы.
- Кэширование результатов (в Map, localStorage, через HTTP-заголовки).
- Debounce для поиска (чтобы не спамить сервер).
- Отмена устаревших запросов (AbortController).
- Пагинация — не грузить всё сразу.
- HTTP-кэш — использовать заголовки Cache-Control, ETag.

## 10. Какие лучшие практики существуют для работы с Fetch API в production приложениях?

- Всегда проверять response.ok.
- Обрабатывать ошибки через try/catch (или .catch()).
- Устанавливать таймауты (через AbortController).
- Использовать обёртку (custom fetchApi), чтобы не дублировать код (добавление токенов, заголовков, обработка 401).
- Кэшировать повторяющиеся запросы.
- Не хранить токены в открытом виде в коде.
- Использовать URLSearchParams для параметров.
- Поддерживать отмену запросов.
- Логировать ошибки (например, в Sentry).
- Тестировать запросы (mocking, nock, MSW).
