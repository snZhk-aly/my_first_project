# Ответы на вопросы для самоконтроля — Практическая работа №15

## 1. В чём разница между функциональными и классовыми компонентами?

Классовые компоненты — это классы, наследующие `React.Component`. Они имеют методы жизненного цикла (`componentDidMount` и др.) и хранят состояние в `this.state`.
Функциональные компоненты — это обычные функции. До появления хуков в них нельзя было использовать состояние. Теперь это стандарт разработки.

Когда использовать:
- Функциональные: всегда, если нет веских причин для обратного. Они короче, проще читаются, легче тестируются.
- Классовые: в старых проектах или если нужны специфические методы, которых нет в хуках (что редкость).

## 2. Что такое props и state? Как они отличаются и какие правила их использования?

- **Props** — входные данные компонента. Передаются от родителя к ребенку. Только для чтения (read-only).
- **State** — внутренние данные компонента, которые могут меняться с течением времени. Инициализируется внутри компонента.

Отличия:
- Props нельзя изменять напрямую.
- State изменяется через `setState` (в классах) или функцию-сеттер из `useState` (в функциях).
- Изменение state вызывает перерисовку компонента. Изменение props (передача новых) тоже вызывает перерисовку.

## 3. Как работает поднятие состояния (lifting state up)?

Если двум компонентам нужно использовать одни и те же данные, состояние «поднимается» в ближайший общий родительский компонент. Родитель хранит state и передаёт его вниз через props, а также передаёт функции для изменения этого состояния.

Это нужно, чтобы синхронизировать данные между разными частями интерфейса.

## 4. Какие методы жизненного цикла классовых компонентов вы знаете?

- `constructor()` — инициализация state, привязка методов.
- `render()` — обязательный метод, возвращает JSX.
- `componentDidMount()` — вызывается после первого рендера (запросы к API, таймеры).
- `componentDidUpdate(prevProps, prevState)` — после обновления (сравнение props/state, повторные запросы).
- `componentWillUnmount()` — перед удалением (очистка таймеров, отписка от событий).
- `shouldComponentUpdate()` — позволяет предотвратить перерисовку (оптимизация).

В функциональных компонентах их заменяет `useEffect`.

## 5. Как работают хуки useState и useEffect? Какие правила использования хуков?

`useState(initial)` возвращает массив из двух элементов: текущее значение и функцию для его изменения. При изменении значения компонент перерисовывается.

`useEffect(callback, deps)` выполняет побочные эффекты после рендера. Второй аргумент (массив зависимостей) определяет, когда эффект запускать:
- Без массива — после каждого рендера.
- С пустым массивом `[]` — только при монтировании.
- С `[dep]` — при изменении `dep`.

Правила хуков:
1. Вызывать только на верхнем уровне (не внутри условий, циклов или вложенных функций).
2. Вызывать только из React-функций (компонентов или кастомных хуков).

## 6. Что такое ключи (keys) в React и почему они важны?

`key` — это специальный атрибут, который помогает React идентифицировать элементы в списке. Когда список меняется (добавление, удаление, сортировка), React использует ключи, чтобы понять, какие элементы изменились, а какие остались прежними.

Без ключей React перерисовывает весь список целиком, что медленно. В качестве ключа лучше использовать уникальные ID из базы данных, а не индексы массива (если список сортируется или фильтруется).

## 7. Как обрабатывать события в React и чем это отличается от нативного JavaScript?

В React события пишутся в camelCase: `onClick`, `onChange`, `onSubmit`. В обработчик передаётся не строка, а функция.

Отличия:
- React использует SyntheticEvent (обёртка над нативным событием) для кроссбраузерности.
- Для предотвращения стандартного поведения используется `event.preventDefault()`. Возврат `false` не работает.
- Контекст `this` в классовых компонентах нужно привязывать вручную (или использовать стрелочные функции).

## 8. Что такое управляемые и неуправляемые компоненты?

- **Управляемые (Controlled)** — значение поля ввода контролируется состоянием React. Каждое изменение поля вызывает `onChange`, обновляет state, и React перерисовывает input с новым значением. Это стандарт.
- **Неуправляемые (Uncontrolled)** — значение хранится в самом DOM. Доступ к нему получают через `ref` (например, `useRef`). Меньше кода, но сложнее валидировать в реальном времени.

## 9. Как работает контекст (Context) в React и когда его следует использовать?

Context позволяет передавать данные через дерево компонентов, не передавая их через props на каждом уровне («prop drilling»).

Создаётся через `React.createContext(defaultValue)`. Оборачиваем дерево в `Provider` и передаём значение. Любой дочерний компонент может получить значение через `useContext` или `Context.Consumer`.

Используется для глобальных данных: текущий пользователь, тема (тёмная/светлая), язык интерфейса.

## 10. Какие преимущества предоставляют кастомные хуки и как создавать собственные хуки?

Кастомный хук — это функция, которая начинается с `use` и вызывает другие хуки. Он позволяет вынести повторяющуюся логику (например, работу с localStorage или fetch) в отдельную функцию.

Преимущества:
- Повторное использование логики (не просто копирование кода).
- Чистота компонентов.
- Легче тестировать.

Создание: просто пишете функцию `function useMyHook() { ... }`, внутри используете `useState`, `useEffect` и т.д., возвращаете нужные данные.
