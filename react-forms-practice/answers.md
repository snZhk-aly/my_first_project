# Ответы на вопросы для самоконтроля — Практическая работа №17

## 1. В чем разница между управляемыми и неуправляемыми компонентами в формах React?

В управляемых компонентах данные формы хранятся в состоянии React (useState). Компонент всегда отображает актуальное состояние, а изменения происходят через обработчики (onChange). Это дает полный контроль над данными и позволяет делать мгновенную валидацию.

В неуправляемых компонентах данные хранятся напрямую в DOM. React не знает об их изменениях, пока не произойдет отправка формы. Доступ к значениям получают через useRef или FormData.

## 2. Когда следует использовать управляемые компоненты, а когда - неуправляемые?

Управляемые используются в 90% случаев: когда нужна валидация "на лету", условный рендеринг полей, зависимые поля (например, выбор города из списка областей) или блокировка кнопки отправки до заполнения формы.

Неуправляемые лучше использовать для очень простых форм (например, форма поиска или подписки), где не требуется валидация, или при интеграции со сторонними библиотеками (например, для загрузки файлов), где управление DOM берет на себя библиотека.

## 3. Какие методы используются для обработки событий в формах React?

В React используются события, написанные в camelCase (например, onChange, onSubmit, onClick). В обработчик передается функция, а не строка. 
Для получения данных из инпута используется event.target (или деструктуризация event.target.value). 

## 4. Как обрабатывать несколько полей ввода с одним обработчиком?

Для этого каждому полю задается атрибут name. В обработчике используется вычисляемое свойство объекта:

const handleChange = (e) => {
  const { name, value, type, checked } = e.target;
  setFormData({ ...formData, [name]: type === 'checkbox' ? checked : value });
};

## 5. Какие подходы к валидации форм в React вы знаете?

1. Встроенная HTML5 валидация (атрибуты required, minLength, type="email"). Браузер сам проверяет и показывает подсказки.
2. Валидация через состояние React (как в Задании 2). При вводе или отправке данные проверяются через JS, и выводятся кастомные сообщения об ошибках.
3. Сторонние библиотеки (Formik, React Hook Form, Yup). Они берут на себя всю рутину по управлению состоянием и валидации.

## 6. Как предотвратить стандартное поведение формы (перезагрузку страницы)?

В обработчике события onSubmit нужно вызвать метод preventDefault() у объекта события:

const handleSubmit = (e) => {
  e.preventDefault();
  // код обработки
};

## 7. Что такое "поднятие состояния" (lifting state up) в контексте форм?

Это паттерн, при котором состояние формы хранится не внутри самой формы, а в родительском компоненте. Родитель передает данные формы дочерним компонентам через props, а также передает функцию для их изменения. Это нужно, когда данные формы используются в других частях приложения (например, при отправке на сервер или для отображения предпросмотра).
