# Ответы на вопросы для самоконтроля — Практическая работа №12

## 1. В чём разница между event.preventDefault() и event.stopPropagation()?

preventDefault() отменяет стандартное поведение браузера для этого события. Например, переход по ссылке, отправку формы, выделение текста.
stopPropagation() останавливает всплытие (или перехват) события. Родительские обработчики не получат это событие.

preventDefault используется, когда нужно сделать «своё» поведение вместо браузерного. stopPropagation — когда обработчик на дочернем элементе не должен вызывать обработчик на родителе.

## 2. Как работает делегирование событий и какие преимущества даёт?

Вместо навешивания обработчика на каждый элемент — вешаем один на родителя. Событие от дочернего элемента всплывает к родителю, где мы его ловим и определяем, по какому именно элементу кликнули (event.target).

Преимущества:
- Меньше обработчиков — лучше производительность.
- Работает для элементов, добавленных после навешивания обработчика.
- Упрощает код при удалении и пересоздании элементов.

## 3. Какие фазы жизненного цикла события существуют?

Три фазы:
1. Capturing (перехват) — сверху вниз: от window к целевому элементу.
2. Target (цель) — событие достигает целевого элемента.
3. Bubbling (всплытие) — снизу вверх: от целевого элемента к window.

По умолчанию addEventListener слушает на фазе всплытия (третий аргумент false). Чтобы слушать на перехвате — передать { capture: true }.

## 4. В чём разница между event.target и event.currentTarget?

event.target — элемент, на котором произошло событие (тот, по которому реально кликнули). Может быть вложенным.
event.currentTarget — элемент, к которому привязан текущий обработчик. Внутри обработчика это this.

target — для делегирования (узнать, на что кликнули). currentTarget — если нужно знать, чей обработчик сейчас работает.

## 5. Как создать и запустить кастомное событие?

Создаём событие через new CustomEvent('имяСобытия', { detail: { ... } }). 
В объекте настроек можно передать:
- detail — любые данные (объект, строка, число).
- bubbles — будет ли событие всплывать.
- cancelable — можно ли его отменить через preventDefault.

Запускается событие через метод element.dispatchEvent(event).

## 6. Что такое debounce и throttle?

- Debounce — откладывает вызов функции на delay после последнего вызова. Если вызовы идут подряд, функция сработает только когда они «затихнут».
- Throttle — ограничивает частоту: не чаще, чем раз в interval. Вызовы внутри интервала игнорируются.

Где применять:
- Debounce — поиск с автодополнением, валидация формы.
- Throttle — скролл, mousemove, drag.

## 7. Какие методы существуют для удаления обработчиков и почему это важно?

- element.removeEventListener('click', handler) — удаляет конкретный обработчик. Нужно передать ту же функцию.
- element.onclick = null — удаляет обработчик, назначенный через свойство.
- AbortController — современный способ удалить сразу группу обработчиков.

Важно:
- Предотвращает утечки памяти.
- Убирает лишние вызовы.
- Помогает, когда элемент удаляется из DOM.
- Позволяет избежать конфликтов обработчиков.

## 8. Как обрабатывать ошибки загрузки ресурсов и какие события используются?

Основные события:
- load — успешная загрузка.
- error — ошибка загрузки.
- loadstart — начало загрузки.
- loadend — завершение (успех или ошибка).
- progress — прогресс загрузки.
- abort — загрузка прервана.

Для картинки создаём new Image(), навешиваем на неё обработчики 'load' и 'error', а затем задаём свойство src. Если загрузка не удалась, сработает 'error', и мы сможем показать заглушку.

## 9. В чём разница между addEventListener и onclick?

- onclick = handler — только один обработчик. Повторное присваивание перезаписывает предыдущий.
- addEventListener('click', handler) — можно добавить несколько обработчиков. Они все будут вызваны по порядку.
- removeEventListener работает только с addEventListener.
- addEventListener поддерживает фазу перехвата (capture: true).

onclick — короче, но менее гибкий. addEventListener — современный стандарт.

## 10. Как оптимизировать производительность при работе с событиями?

- Делегирование — один обработчик на родителя вместо сотни на детей.
- Debounce / throttle для частых событий (scroll, resize, mousemove, input).
- Использовать опцию { passive: true } для скролла — браузер не будет ждать выполнения обработчика.
- Удалять ненужные обработчики через removeEventListener или AbortController.
- Не вешать тяжёлые вычисления прямо в обработчик — выносить в requestAnimationFrame или setTimeout.
- Использовать { once: true }, если обработчик нужен только один раз.
- Не создавать обработчики внутри циклов — выносить наружу.
