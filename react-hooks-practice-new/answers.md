# Ответы на вопросы для самоконтроля — Практическая работа №16

## 1. В чём разница между useState и useReducer?

`useState` — простой хук для базовых состояний (число, строка, boolean). Идеален для независимых друг от друга значений.

`useReducer` — используется для сложной логики. Принимает функцию-редьюсер и начальное состояние. Возвращает текущий state и метод dispatch для отправки действий. Лучше подходит, когда новое состояние зависит от предыдущего или когда у состояния много полей.

## 2. Как работает useEffect и для чего нужен второй аргумент?

`useEffect` выполняет побочные эффекты (запросы, подписки, таймеры) после рендера.
Второй аргумент — массив зависимостей:
- Не указан: эффект срабатывает после каждого рендера.
- `[]`: только при монтировании (и очистка при размонтировании).
- `[dep]`: при изменении `dep`.

## 3. Что такое useContext и как он решает проблему "prop drilling"?

Контекст позволяет передавать данные на любую глубину дерева компонентов без использования props.
"Prop drilling" — это когда данные передаются через много промежуточных компонентов, которым они не нужны. `useContext` позволяет сразу получить данные в нужном компоненте.

## 4. В чём разница между useMemo и useCallback?

- `useMemo` кэширует результат вычисления функции (возвращает значение). Нужен для тяжёлых вычислений.
- `useCallback` кэширует саму функцию (возвращает ссылку), чтобы она не создавалась заново при каждом рендере. Нужен при передаче функций в дочерние оптимизированные компоненты.

## 5. Как работает useRef и в каких случаях его использовать?

`useRef` возвращает объект с полем `current`. Изменение этого поля не вызывает перерендер.
Используется для:
- Доступа к DOM-элементам (фокус, скролл).
- Хранения предыдущего значения между рендерами.
- Хранения таймеров (чтобы очищать их).

## 6. Какие правила использования хуков существуют?

1. Вызывать только на верхнем уровне (не внутри условий, циклов или вложенных функций).
2. Вызывать только из React-функций (компонентов или кастомных хуков).
3. Имя кастомного хука должно начинаться с `use`.

## 7. Как создавать кастомные хуки и зачем они нужны?

Кастомный хук — это функция (начинается с `use`), которая вызывает другие хуки. Нужен для вынесения повторяющейся логики (например, `useLocalStorage` или `useFetch`) в отдельное место, чтобы не дублировать код в разных компонентах.
