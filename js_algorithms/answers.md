# Ответы на вопросы для самоконтроля — Практическая работа №9

## 1. В чём разница между временной сложностью O(n) и O(n²)? Приведите примеры.

O(n) — линейная сложность: время выполнения растёт пропорционально количеству элементов. Удвоили массив — примерно вдвое дольше.
Примеры: findMax, countVowels, reverseString, isPrime (с оптимизацией до sqrt).

O(n²) — квадратичная: время растёт как квадрат количества. Удвоили массив — в 4 раза дольше.
Примеры: bubbleSort, вложенные циклы по одному массиву.

Разница критична на больших данных: при n = 10000 алгоритм O(n²) сделает ~100 млн операций, а O(n) — всего 10 тыс.

## 2. Как работает бинарный поиск и почему его сложность O(log n)?

Алгоритм работает только на отсортированном массиве. На каждом шаге:
- находим середину;
- сравниваем target с элементом посередине;
- если равно — вернули индекс;
- если target меньше — ищем в левой половине;
- если больше — в правой.

Каждый шаг отбрасывает половину оставшихся элементов. После k шагов остаётся n / 2^k элементов. Когда остаётся 1, k ≈ log₂(n). Отсюда сложность O(log n).

## 3. Преимущества и недостатки пузырьковой сортировки.

Преимущества:
- Очень простая реализация.
- Понятна для обучения.
- Устойчивая (не меняет порядок равных элементов).
- С оптимизацией «если не было обменов — выходим» даёт O(n) на почти отсортированных данных.

Недостатки:
- O(n²) в среднем и худшем случае.
- Медленная на больших массивах.
- На практике почти всегда проигрывает быстрой сортировке, сортировке слиянием и встроенному sort.

## 4. Как оптимизировать функцию проверки на простое число для больших чисел?

- Проверять делители только до sqrt(n), а не до n.
- Сразу отбрасывать чётные числа (кроме 2) и кратные 3.
- Проверять только нечётные делители.
- Использовать вероятностные тесты (Миллера-Рабина) для очень больших чисел.
- Использовать решето Эратосфена, если нужно проверить много чисел сразу.
- Для криптографических задач — специальные библиотеки.

## 5. Разница между рекурсивной и итеративной реализацией Фибоначчи.

Рекурсивная:
function fib(n) {
  if (n <= 1) return n;
  return fib(n - 1) + fib(n - 2);
}
Плюсы: короткая запись, близка к математическому определению.
Минусы: экспоненциальная сложность O(2^n) из-за повторных вычислений; риск переполнения стека на больших n.

Итеративная:
Плюсы: O(n) по времени, O(1) по памяти, нет риска переполнения стека.
Минусы: чуть более многословная запись.

Рекурсию можно улучшить мемоизацией — тогда сложность тоже станет O(n).

## 7. Как работает алгоритм Евклида и почему он эффективен?

Алгоритм основан на свойстве: НОД(a, b) = НОД(b, a mod b).
Повторяем, пока второе число не станет 0. Тогда первое число и есть НОД.

Пример: gcd(54, 24) → gcd(24, 6) → gcd(6, 0) → 6.

Эффективность: на каждом шаге числа уменьшаются как минимум вдвое (в среднем гораздо быстрее), поэтому сложность O(log(min(a, b))). Это очень быстро даже для больших чисел.

## 8. Какие edge cases нужно учитывать при работе с массивами?

- Пустой массив.
- Массив из одного элемента.
- Массив с одинаковыми элементами.
- Массив с отрицательными числами.
- Массив с нулями (важно для деления).
- Массив с NaN или undefined.
- Очень большой массив.
- Уже отсортированный / отсортированный в обратном порядке.
- Массив с вложенными массивами (если алгоритм рекурсивный).

## 9. Как улучшить функцию удаления дубликатов для больших массивов?

Мой вариант через Set уже O(n) по времени, но требует памяти O(n) на сам Set.

Для больших массивов:
- Set — самый быстрый вариант для примитивов.
- Для объектов — использовать Map по уникальному ключу.
- Если массив уже отсортирован — удалять соседние дубликаты за один проход, O(n) по времени и O(1) по памяти.
- Если порядок не важен — сортировка + проход.
- Для потоковой обработки — обрабатывать частями.

## 10. Какие принципы чистого кода вы применили?

- Понятные имена функций и переменных (isPrime, countVowels, а не f1, f2).
- Каждая функция делает одну вещь.
- Комментарии о сложности и назначении.
- Нет магических чисел — всё вынесено в переменные.
- Не мутируем входные данные (bubbleSort возвращает копию).
- Обработка edge cases (пустой массив, отрицательные числа, null).
- Единый стиль отступов и кавычек.
- Разделение на файлы: логика отдельно, тесты отдельно.
